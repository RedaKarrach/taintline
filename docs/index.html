incident response for a hijacked AI agent · MIT · github.com/RedaKarrach/taintline

What this is for. An AI agent reads web pages, emails and files, then acts on what it read. A page can carry a line written for the agent, not for you: do this, do not tell the user. The agent reads it like any other text. That is prompt injection, and it leaves a trail. taintline reads the agent's own log and answers three questions: did something untrusted steer it, what left, and where did it go. It can also stand in front of the agent and refuse the call before anything leaves.

Seven questions, one command each. Run it, read what it prints, take the arrow down. The output below is what taintline really prints, from a simulated incident with made-up names.

Press enter, or tap the command line, to run the first one.

END OF TRANSMISSIONRun it yourself.

$ uv tool install git+https://github.com/RedaKarrach/taintline
# or: pipx install git+https://github.com/RedaKarrach/taintline
$ taintline analyze trace.jsonl --out report/ --dashboard        # what happened, with evidence
$ taintline guard replay trace.jsonl                             # where the guard would have stopped it
$ taintline guard mcp-proxy --audit audit.jsonl -- your-mcp-server   # stop the next one, no code changes
$ taintline forensics pack build trace.jsonl --sign-key ir.key --out pack.json   # signed evidence
# feeding it your own agent
one JSON line per thing the agent does: user_message, model_output, tool_call, tool_result, memory_write, memory_read.
adapters for OpenAI chat logs and OpenTelemetry GenAI spans: --format openai|otel. see docs/trace-format.md.
# what it cannot do
- it reads logs. what was never logged, it cannot see.
- the wording checks are plain regexes. a smoothly paraphrased instruction can pass them; the behaviour checks and the guard still catch what it tries to do.
- it is one layer. keep your input and output filters and least-privilege tools.
