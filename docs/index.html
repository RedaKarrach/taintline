The clever bit

Most tools read an incoming message and guess "does this look dangerous?" taintline asks a sharper one: "did the dangerous thing actually happen?"

A web page that mentions API keys is fine. A web page that talks your agent into mailing one out is not. taintline only fires when bad input genuinely flows into a bad action — so it stays quiet during real work and shouts when it counts.

Three ways to put it to work

Same engine, whether you're cleaning up after an incident or trying to prevent the next one.

🔎 Analyze

Something went sideways. Reconstruct exactly what happened, with evidence.

taintline analyze trace.jsonl \
  --out report/ --dashboard

🛡️ Guard

Don't let it go sideways. Block dangerous calls live — zero changes to your agent.

taintline guard mcp-proxy \
  -- your-mcp-server

📡 Pipeline

Wire it into CI or a SIEM. Fail the build if a trace leaks.

taintline analyze traces.jsonl \
  --fail-on high

The Guard is the showpiece: it runs every tool call through the taint engine first and decides — allow, log, ask a human, or block — in a millisecond and a half. Drop it in front of any Model Context Protocol server and your agent is covered.
